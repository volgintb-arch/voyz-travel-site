# VOYZ Travel

Статический сайт авторских путешествий по Кыргызстану. Сейчас опубликован **один маршрут — Grand Expedition**: 8 маршрутных дней / 7 ночей, группа **6–12 путешественников**, сезон июнь–сентябрь, старт и финиш в Бишкеке. Цены не опубликованы. Шесть прежних концептов хранятся в `data/archive/` и в действующий каталог не входят.

Предпросмотр: https://volgintb-arch.github.io/voyz-travel-site/
Instagram: https://www.instagram.com/voyz_travel/

## Как устроен сайт

- Обычные HTML/CSS/JS без серверной сборки и без npm. `build_site.py` генерирует страницы из JSON.
- Два языка: русский `/` и английский `/en/`. По пять основных страниц: главная, каталог, Grand Expedition, политика и авторы фото.
- **Один адаптивный сайт на всех экранах.** До 1024 px появляются компактная шапка и нижняя навигация; отдельного приложения нет. Старые `/app/` и `/en/app/` перенаправляют на сайт, сохраняя язык и маршрут из старого hash-адреса.
- Десктопная вёрстка растягивается до 1600 px; на больших экранах `assets/scale.js` масштабирует композицию.
- При одном туре календарь сезонов и сравнение маршрутов скрыты. Они появляются, если добавить ещё один активный тур.
- В проекте есть карта, фотогалереи, локальные видео, stories-плеер, FAQ и форма заявки. Анимации учитывают `prefers-reduced-motion`.
- Фирменный стиль: логотип VOYZ, Unbounded, Mulish, чёрный, белый и лайм `#D8FC00`.

## Основные файлы

| Файл | Назначение |
|---|---|
| `data/tours.json` | Флагман: программа, группа, сезон, FAQ, фотографии |
| `data/tours_extra.json` | Дополнительные активные туры (сейчас список пуст) и общие значения |
| `data/tour_template.json`, `new_tour.py` | Шаблон и заготовка нового тура |
| `data/archive/` | Архивные концепты, не публикуются |
| `data/en.json` | RU → EN, словарь перевода HTML и структурированных данных |
| `data/team.json` | Павел, ссылки на Instagram, актуальное и выбранные публикации |
| `assets/team/`, `assets/social/` | Локальные фото профиля и обложки публикаций VOYZ |
| `assets/config.js` | Адрес приёма заявок, Telegram, WhatsApp, телефон, email |
| `build_site.py` | Общие шаблоны и генерация RU/EN, sitemap, метаданных и 404 |
| `build_app.py` | Только совместимость старых ссылок `/app/` |
| `assets/site.css`, `v2.css`, `mobile.css` | Базовые стили, оформление секций, адаптация |
| `assets/site.js`, `v2.js`, `stories.js` | Формы, галереи, анимации, stories-плеер |

Готовые `index.html`, `tours/`, `en/`, `privacy/`, `credits/` коммитятся для GitHub Pages. **Редактируйте данные и шаблоны**, затем пересобирайте: ручные правки сгенерированного HTML будут перезаписаны.

## Сборка и локальный просмотр

Для генерации нужен Python 3 без дополнительных библиотек:

```bash
python build_site.py
python build_app.py
python -m http.server 8765
```

Открыть http://localhost:8765/. `build_site.py` сообщает о пропущенных переводах в `data/en_missing.json`. Английскую редакцию стоит вычитать перед запуском.

При изменении заголовков/набора туров пересоберите картинки соцсетей через `python make_og.py`, при изменении иконок — `python make_icons.py` (для этих скриптов нужен Pillow).

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
python test_all.py
python test_app.py
python audit.py
```

Тесты сами запускают изолированный HTTP-сервер на свободном порту. Для уже работающего сервера задайте `BASE_URL`. Список маршрутов берётся из активных JSON, архивные туры не проверяются как опубликованные страницы.

- `test_all.py`: все активные RU/EN-страницы, метаданные, JSON-LD, sitemap, внутренние URL и якоря, переводы, Instagram/команда, группа 6–12, поля формы до 12 участников, валидация, локальный демо-режим и имитация успешной отправки без реальных заявок, FAQ и галерея. При ошибках ненулевой код завершения.
- `test_app.py`: старые адреса `/app/` ведут на текущий сайт с правильным языком и туром на телефоне и компьютере.
- `audit.py`: переполнение страницы и элементов, обрезанный текст и разрывы слов на всех активных RU/EN-страницах. По умолчанию ширины 320, 390, 768, 1024, 1440, 1920, 2560 px. Можно указать свои: `python audit.py 390 1440`. Намеренно прокручиваемые области и декоративные кадрированные фото не считаются ошибками.
- `visual_check.py`: снимки страниц и основных секций в `shots/` для визуальной проверки (эта папка не коммитится).

## Команда и Instagram

Блок о Павле и Instagram показан на главной и Grand Expedition; ссылка на профиль есть в подвале всех страниц. Данные, фото и точные ссылки на публикации находятся в `data/team.json`. Снимки хранятся локально: сайт не зависит от временных CDN-ссылок Instagram и не загружает сторонний embed-скрипт.

Источник фактов — открытый профиль @voyz_travel, проверен 5 ноября 2026: имя Павел, основатель VOYZ, авторские джип-туры, 60+ организованных путешествий. Истории «Обо мне» требуют входа, поэтому непроверенные биографии других гидов и обещания персонального сопровождения Павлом не добавлены. Фото профиля — 150×150, используется небольшим аватаром; для крупного портрета нужен оригинал. Чтобы добавить подтверждённого гида, дополните `members`, положите фото в `assets/team/`, добавьте переводы и пересоберите сайт.

## Заявки и контакты

`assets/config.js`: заполните `formEndpoint`, если есть реальный сервис, принимающий JSON POST; остальные контакты показываются только при заполнении.

Сейчас endpoint и прямые контакты пустые: **форма работает в демо-режиме**, сохраняет заявку в `localStorage` устройства посетителя и предлагает её скопировать. Организатору такая заявка не приходит. Instagram доступен отдельной ссылкой. Не храните секретные ключи в публичном JS.

В форме число участников — это число людей, оставляющих совместную заявку; можно выбрать 1–12 или «Больше 12» для обсуждения индивидуального маршрута. Размер группы флагмана — 6–12.

## Перед публикацией на основном домене

1. Подключить реальный приём заявок и заполнить подтверждённые контакты.
2. В `build_site.py` поменять `SITE_URL` на основной домен и `INDEXABLE = True`, заполнить нужные `VERIFY`. Сейчас предпросмотр закрыт `noindex,nofollow`.
3. Пересобрать сайт, редиректы и OG-изображения, запустить проверки и затем публиковать.
4. Согласовать реквизиты и политику конфиденциальности; подтвердить права на фото из архива. Авторство лицензированных фото указано в `credits/`.
5. Вычитать английскую версию и проверить программу/условия размещения перед продажами.

Новый тур: `python new_tour.py my-slug "Название тура"`, затем заполнить данные и переводы, выполнить сборку и проверки. Сами концепты из архива автоматически не публикуются.
